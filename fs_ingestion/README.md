# fs_ingestion — Group financial statements (.docx) → bronze

Reads the two Group FS Word documents into `bronze.fs_clean` and
`bronze.fs_seeded`, per the **Group FS Ingestion Notes (17 Aug)**.

**Self-contained on purpose.** This package shares no code with
`bronze_ingest` so the two can be reviewed and merged independently. Where a
convention is duplicated rather than imported — the CSV writer, the
`IngestError` name, the three-phase push script — it is duplicated
deliberately and marked as such, so merging later is a deletion rather than a
rewrite. See [Integrating later](#integrating-later).

```
pip install -e .            # or: pip install -r requirements.txt
python -m fs_ingest         # both documents -> outputs/*.csv
python scripts/roundtrip_check.py
python -m unittest discover -s tests
python scripts/push_to_bq.py --check
```

Source documents go in `data/` (gitignored — the pack is synthetic but
client-shaped):

```
data/PoC_Group_FS_clean.docx
data/PoC_Group_FS_seeded.docx
```

## The three rules that make this table pair different

### 1. It never refuses to land on an arithmetic break

Every extractor in `bronze_ingest` raises when the numbers disagree —
`group_tb` refuses to land a trial balance that does not prove to nil.
**This one inverts that.** `fs_seeded` carries three deliberately planted
defects and they are the deliverable:

| Defect | Printed | Should be | Signal |
|---|---|---|---|
| Total current assets | 683,180 | 682,760 | breaks the subtotal **and** the Total assets rollup |
| Revenue from contracts with customers | 423,221 | 423,218 | breaks the subtotal **and** External revenue |
| `Borrowings (Note 5)` in non-current liabilities | Note 5 | Note 9 | **none** — text only |

An extractor that footed the statements and refused would be unable to
ingest the document the PoC exists to examine. So ingest checks **structure
only** — did we read the page correctly — and every arithmetic question is
left to silver, where a break becomes a finding.

That third defect is why `label` keeps the note reference verbatim instead of
splitting it into a tidy `note_ref` column. It carries no arithmetic signal
at all; preserving the text is the only thing that makes it findable.

### 2. It is typed, unlike every other bronze table

`value NUMERIC`, `is_bold BOOL`, `row_ord INT64` — against the all-STRING
bronze contract ("every value lands as text"). Ruled in favour of the
Ingestion Notes: footing checks run at zero tolerance, and binary floating
point manufactures breaks that are not in the document. `Decimal` is used
end-to-end in Python so the argument holds there too and not only in the DDL.

Consequence worth knowing: the Ingestion Notes declined a `value_text`
companion column, so a cell that failed to parse would land as `NULL` and be
indistinguishable from a legitimately blank one. That fidelity is not
persisted anywhere, so it is checked at read time instead — a figure that
does not parse **stops the load**. That is a reading failure, not an
arithmetic one.

### 3. `section` and `subsection` are derived, not observed

The only two interpreted columns in the table. The pages do not print the
hierarchy consistently:

| Value | Printed on the page? |
|---|---|
| `section = 'Equity and liabilities'` | **yes** — bold header row |
| `section = 'Assets'` | **no** — the balance sheet opens at "Non-current assets" |
| `subsection = 'Equity'` | **no** — goes "Equity and liabilities" → "Share capital" |
| `section = 'Operating costs'` | **no** — the income statement prints no group headers at all |

Rather than bury that in a heuristic, the ranges are declared by label in
`configs/fs_*.json`, where a reviewer can hold them against the printed page.
Every anchor is verified to resolve exactly once, so a config that drifts
from the document fails the load rather than mis-assigning rows.

## Layout

```
src/fs_ingest/
  errors.py       IngestError — reading failures only, never arithmetic
  word.py         .docx -> tables + bold. Knows nothing about statements
  statements.py   tables -> bronze rows. The contract and the checks
  schema.py       columns, types, and the BigQuery column descriptions
  sink.py         CSV writer
  cloud.py        GCS + BigQuery adapters (imported lazily, so tests run offline)
  __main__.py     python -m fs_ingest
configs/          one per document; the derived hierarchy lives here
sql/              GENERATED by scripts/generate_ddl.py — do not hand-edit
scripts/
  generate_ddl.py    regenerate sql/*.sql from schema.py
  roundtrip_check.py exhaustive extraction proof (see below)
  push_to_bq.py      create -> load -> verify
tests/            unittest; 38 tests, no pytest needed
```

`configs/fs_seeded.json` is identical to `fs_clean.json` apart from
`input_path` and `output_file`, **and must stay that way** — any difference
between the two tables has to come from the documents, never from two configs
that drifted.

## Verification

Three layers, cheapest first.

**Structural checks at ingest** (in `statements.py`) — statement set and
order, hierarchy anchors resolve exactly once, no empty `NOT NULL` column,
every figure-shaped cell parsed, natural key
`(statement, row_ord, column_label)` unique.

**`scripts/roundtrip_check.py`** — renders every stored row back into the
string the page shows (commas restored, negatives re-parenthesised) and diffs
against a fresh read of the `.docx`. Both documents together are 304 value
cells, so this is **exhaustive, not a sample** — it proves extraction is
correct rather than plausible. A production pipeline could not afford this; a
one-time load of two known documents can.

```
[OK] fs_clean:  152 rows, 152 value cells, 0 mismatch(es)
[OK] fs_seeded: 152 rows, 152 value cells, 0 mismatch(es)
```

**`scripts/push_to_bq.py` phase 3** — re-queries BigQuery after the load, so
it proves the *loaded table* is right rather than that the CSV was. Notably
it asserts the types survived: this is the only non-STRING table pair in
bronze, so a regression to the all-STRING default would land silently and
surface much later as a wrong answer.

## Expected shape

152 rows per document, 304 total.

| Statement | Lines | Columns | Rows |
|---|---:|---:|---:|
| Consolidated statement of income | 19 | 2 | 38 |
| Consolidated balance sheet | 43 | 2 | 86 |
| Note 5 — Property, plant and equipment | 7 | 1 | 7 |
| Note 7 — Income taxes and zakat | 5 | 1 | 5 |
| Note 9 — Borrowings | 3 | 3 | 9 |
| Note 10 — Revenue | 7 | 1 | 7 |

`row_ord` is the line's position on the **page**, not in the table, so it
repeats once per column — Inventories appears twice at `row_ord 11`, once per
period.

The only rows with `value IS NULL` are the balance sheet's five bold group
headers, once per period — 10 rows.

## Two traps worth knowing

**Bold.** Word writes a non-bold run as an explicit `<w:b w:val="0"/>`, not
by omitting the tag — 168 of them against 76 real `val="1"` in this pack. A
reader that tests for the tag's *presence* marks every row bold, which
destroys subtotal detection while appearing to work. `python-docx` models
bold as a tri-state and is the reason it is a dependency. `tests/test_word.py`
asserts the fixture really emits `val="0"`, so the trap cannot stop being
exercised.

**The em dash.** Note headings use U+2014 (`Note 9 — Borrowings`), not a
hyphen. Equality filters must match the character exactly.

## Integrating later

Merging into `bronze_ingest` is mostly deletion:

- `errors.py` → drop; use `bronze_ingest.excel.IngestError` (same name and
  meaning, chosen for exactly this).
- `sink.py` → drop; identical to `bronze_ingest/sink.py`, including the
  `lineterminator` argument, so the CSV bytes match.
- `word.py`, `statements.py`, `schema.py` → move under
  `bronze_ingest/`; add `python-docx` to its requirements.
- `cloud.py` → `bq_schema()` there hardcodes `STRING`; it needs an optional
  per-table `types` dict defaulting to `STRING` so the other six tables are
  unaffected. Thread it through `_load_config()` and both loaders.
- `push_to_bq.py` → add the two tables to `EXPECTED_ROWS` and add `verify()`
  here as a dispatch branch. **`TableState` needs a `types` field.**
- Registry → add `("fs_clean", statements, "fs_clean.json")` and the seeded
  twin to `TABLES`.

One genuine conflict to settle at merge time: `bronze_ingest`'s load config
sets `null_marker="\N"` so that empty cells land as empty strings and bronze
holds no NULLs at all — and its verification asserts that. This pair needs
its NULLs. It resolves without changing the setting, because these rows
*emit* the marker explicitly rather than relying on empty fields, but the
verification checks pull in opposite directions and should not be shared.
